# 기가차드 · 2일차 「내 PC 상태」 실제 측정

> 구현 기록: 2026-10-26. 22단계 제출 이력과 별개로 이어 만든 학생 기능이다. 이 문서는 코드/검사 결과와 사용자 PC의 직접 관찰을 구분한다.

## 1. 제공 기능 확인과 학생이 변경한 범위

작업 전 `on-client` 전체에서 「내 PC 상태」, CPU·메모리·디스크 측정 코드를 검색했으나 **제공 측정 기능은 없었다**. 기존의 `보호 현황`, `업무 앱`, `보안 기록`, 학생 `renderIdentity`~`renderVulnerabilities`는 보존했다.

| 구분 | 파일 | 담당 기능 |
|---|---|---|
| 제공 기능(보존) | `public/app.js`, `student/extension.mjs`, `src/engine.mjs` | 13~20단계 화면 상태와 예제/미연결/실제 엔진 구분 |
| 제공 서버(최소 연결 변경) | `src/server.mjs` | 기존 로컬 Host/Origin 검사 및 응답 형식을 유지하며 읽기 전용 `GET /api/pc-status`와 화면 모듈 정적 경로 추가 |
| 학생 신규 측정 | `src/pc-status.mjs` | Node.js 운영체제 API로 CPU·메모리·디스크를 각각 측정. 오류가 나면 항목별 확인 불가 |
| 학생 신규 표시 | `public/pc-status.mjs` | 안전한 DOM `createElement`·`textContent`로 단위, 측정 시각, 출처, 실패, 직전 측정 비교 표시 |
| 학생 화면 위치/스타일 | `public/index.html`, `public/style.css` | 기존 보호 현황 첫 부분에 측정 카드 3개와 재측정 버튼을 추가, 기존 메뉴와 버튼 유지 |
| 학생 검사 | `tests/pc-status.test.mjs` | 정상 측정·개별 실패·CPU 변화 없음 검증 |

## 2. 측정값의 정확한 의미

| 항목 | 화면 단위 | 측정 방식/한계 | 측정 실패 |
|---|---|---|---|
| CPU 사용률 | `%` | Node.js `os.cpus()`의 논리 CPU 누적 시간 두 표본을 **약 500ms** 간격으로 비교한 전체 사용률. 작업 관리자 순간값과 정확히 같지 않을 수 있음 | `확인 불가` |
| 메모리 사용량 | `GiB` | `os.totalmem()` − `os.freemem()`; 전체 메모리와 함께 표시. Windows 작업 관리자의 캐시/압축 분류와 수치가 다를 수 있음 | `확인 불가` |
| 디스크 남은 공간 | `GiB` | `fs.statfs()`로 **앱 폴더가 있는 드라이브/파일시스템의 사용 가능 공간**을 측정. 모든 드라이브 합계가 아님 | `확인 불가` |

1 GiB = 1,073,741,824바이트이다. 각 항목의 `measuredAt`은 측정 완료 시각(ISO)이며 화면에는 한국시간(KST)으로 표기한다. API의 `checkedAt`은 응답 완성 시각이다. 측정값이 **정확히 0인 경우**와 측정하지 못한 경우는 다른 상태로 구분한다. 빈 결과에 0이나 가짜 예제 수치를 채우지 않는다.

이 기능은 **앱 서버(Node.js)가 실행 중인 컴퓨터**를 측정한다. 학생 Windows PC에서 앱을 직접 켜면 그 PC의 값이고, 실습용 컨테이너에서 실행하면 컨테이너 호스트/가상환경의 값이다. GitHub 소스만 열어서는 PC 값이 나타나지 않는다. 기존 SDP·CLCO 연결 상태 또는 `npm run demo`의 예제 신원·사건을 이 측정값과 혼동하지 않는다.

## 3. 선택한 개선 1가지: 직전 측정 비교

- 화면이 열린 뒤 현재 측정값을 한 번 읽는다.
- **「지금 다시 측정」** 버튼을 누르면 새 값을 읽고, 직전 성공 응답과 CPU 사용률의 %p 차이·메모리 사용량 GiB 차이·디스크 남은 GiB 차이를 텍스트로 표시한다.
- 처음 한 번은 비교할 전 측정이 없다고 명시한다. 개별 측정이 실패한 항목의 비교는 `확인 불가`로 남긴다.
- 지난 두 회의 화면 값만 메모리에서 비교하며 파일·브라우저 저장소에 장기 기록을 저장하지 않는다. 장기 시계열 그래프·알림이라고 주장하지 않는다.

## 4. 사용자 Windows PC에서 재현하기

기존 `GIGACHAD\on-client` 폴더에서 PowerShell을 열고 아래 명령을 차례로 실행한다. 제공 실행 도구를 재사용하며 인증/설정 파일을 복사하지 않는다.

```powershell
node --version
npm run check
node --test tests/pc-status.test.mjs
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

브라우저 `http://127.0.0.1:5189/` → **보호 현황** → **내 PC 상태**를 확인한다.

1. CPU `%`, 메모리 사용량 `GiB`, 디스크 남은 공간 `GiB`를 확인한다. 값 옆에는 `실제 로컬 측정 · 예제 값 아님` 또는 `확인 불가`가 표시된다.
2. 각 카드의 **측정 시각(KST)**이 표시되는지 확인한다. 값을 읽지 못한 경우 숫자 0이나 예제 값으로 대체하지 않는지 확인한다.
3. **「지금 다시 측정」**을 눌러 측정 시각이 갱신되는지, 직전 측정 비교가 나타나는지 확인한다.
4. 실행 PowerShell에서 `Ctrl+C`로 종료하고 다시 같은 명령으로 실행해 화면을 재확인한다.

## 5. 검증·미확인 구분

- **코드 검증 대상**: `node --check` 및 `node --test tests/pc-status.test.mjs`의 정상/실패 모의 입력. 테스트에 넣는 숫자는 **테스트 데이터**이지 학생 PC 실제값이 아니다.
- **실행 검증 대상**: 별도 실습 환경에서 앱 HTTP 200, 읽기 전용 `/api/pc-status` 응답과 세 항목의 `measuredAt`, 다시 측정 시 값 갱신을 확인한다. 그 환경의 숫자는 학생 Windows PC의 측정값이 아니다.
- **사용자 직접 확인 필요**: Windows 11 PC의 실제 CPU·메모리·드라이브 값, 브라우저 버튼과 화면 표기, Windows 재실행, 디스크 측정 API의 해당 Windows 환경 지원 여부. 캡처할 때 `확인 불가` 또는 예제 수치를 실제 측정이라고 쓰지 않는다.

비밀번호·토큰·인증 경로·드라이브의 절대 경로는 API로 반환하지 않는다. 외부 유료 AI 호출, 보안 조치 집행, 패키지/드라이버 설치는 이 측정에 사용하지 않는다.
