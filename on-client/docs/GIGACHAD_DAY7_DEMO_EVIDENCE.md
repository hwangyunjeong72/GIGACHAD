| 영역 | 구현 주체·근거 파일 | 화면에서 확인할 내용 | 현재 증거 등급 |

## 2. 처음부터 끝까지 시연할 핵심 기능 3가지

시연 목표 시간은 약 6분이다. **아래는 시연 계획이며, 사용자 PC에서 연습·실행했다는 진술이 아니다.** 현장에서 실패하면 그 상태와 이유를 그대로 기록한다. 보안 설정 변경·관리자 권한 획득·침투 시험은 하지 않는다.

| 순서 | 실제 시연 행동 | 보여 줄 결과와 증거 | 미확인 시 조치 |
|---|---|---|---|
| **1. 내 PC 측정 (약 2분)** | `on-client`에서 앱 시작 → 브라우저 `보호 현황` → 학생 **상단 4카드** → `PC 요약 다시 조회` | CPU `%`, 메모리·디스크 `GiB`, 각각의 **측정 시각**, SDP 별도 표시. **E01 화면 캡처** | 값을 못 읽으면 수치 대신 `확인 불가`와 표시된 이유를 E01에 기록 |
| **2. 직전 비교·재조회 (약 2분)** | `PC 요약 다시 조회`를 한 번 더 누르고 조회 중 안내·직전 비교 영역 확인 | 실제 조회 두 번의 측정 시각과 변화량. **E02 화면 캡처** | 비교에 필요한 두 측정이 없으면 `비교 불가`를 기록. 오류가 실제 발생한 경우에만 원인·다음 행동을 캡처하며 일부러 연결을 끊지 않음 |
| **3. 네트워크·방화벽·이벤트 (약 2분)** | 아래 **제공** `내 PC 상태`에서 `내 PC 확인` → 네트워크·Windows 방화벽·Windows 기록을 순서대로 읽음 | 네트워크 인터페이스·IPv4 **구성 개수**, 방화벽 프로필 상태, 최근 24시간 System·Application 합계 경고·오류 건수와 측정 시각. **E03 화면 캡처** | 권한 부족/미지원 항목은 이유와 함께 `확인 불가`. 숫자가 0인 경우도 정상 수집된 `0`인지 확인하고, 침해 판정으로 해석하지 않음 |

마지막에 실행 창에서 `Ctrl+C`로 종료하고 다시 시작해 접속되는지 확인한다. 재실행 성공도 **실제로 확인한 경우에만** 기록한다.

## 3. 증거 목록과 실제 확인 상태

| ID | 증거 종류 | 현재 상태(작성 시점) | 기록·제출 시 확인 사항 |
|---|---|---|---|
| E01 | **사용자 PC 실제 측정 화면** | **미수집·미확인** | CPU·메모리·디스크 값/단위/측정 시각, 사용자 PC에서 직접 조회했는지 |
| E02 | **사용자 PC 두 번 조회·추이 화면** | **미수집·미확인** | 두 번의 측정 시각, 증감·변화 없음·비교 불가 중 실제 표시 |
| E03 | **사용자 PC 네트워크·방화벽·이벤트 화면** | **미수집·미확인** | 제공 기능 표시, 읽기 권한/확인 불가 이유, Windows 경고·오류는 침해 판정이 아님 |
| E04 | **소스·모의 계약 검사 기록** | **확인** · 2026-10-28, 격리 Linux/Node `v24.22.1`, npm `11.9.0` | `npm run check` 통과, `tests/pc-status.test.mjs` **6/6**, `tests/windows-observation.test.mjs` **8/8** 통과. Windows 실측 증거로 사용하지 않음 |
| E05 | **최종 Git 커밋·GitHub 원문** | 작업 시작 SHA `1d799c79133b64bb38b00a16a25810ae98276653` 확인. **7일차 최종 SHA는 커밋 후 확인** | `git rev-parse HEAD`의 40자리 값과 GitHub `main`의 HEAD가 같은지 대조 |
| E06 | **실제 Windows 종료·재실행/독립 시연** | **미수집·미확인** | 직접 수행한 시각, 막힌 단계, 정확한 오류 문구와 재시도 결과 |

화면 캡처를 나중에 제공받으면 **사용자가 직접 확인한 날짜·시간(KST), 측정 출처(실제 로컬 PC/예제/모의), 관찰 결과, 실패 원인**을 추가한다. 캡처가 없는 지금은 파일명·수치·실행 시각을 만들지 않는다. 캡처와 로그에 계정 토큰·비밀번호·인증 번호·개인 IP·이벤트 원문을 넣지 않는다.

## 4. 남아 있는 한계

1. **Windows 사용자 PC 실측 미확인:** 현재 문서는 코드와 격리 환경 검사에 근거하며 사용자 PC의 CPU·메모리·디스크 수치를 대신 제시할 수 없다.
2. **방화벽·이벤트 실제 권한 미확인:** 일반 권한 읽기가 거부되면 `확인 불가`와 이유를 보존한다. 제공 조회는 System·Application 기록 **합산**이며 로그별 건수를 보증하지 않는다. 일부 집계 가능성(최대 5,000건)을 기록한다.
3. **SDP·AI·실제 보안 조치 미확인:** 로컬 PC 상태/예제 화면이 성공했다고 실제 서버 연결·자동 차단·유료 AI 사용이 이뤄진 것은 아니다. 19단계 실집행도 별도 확인이 필요하다.
4. **포장 의도적으로 미실행:** 이번 작전은 소스 폴더 실행이다. `npm run package-app`을 실행하지 않으며, 실행형 패키지·바로가기 설치 성공이라고 하지 않는다.
5. **독립 시연·공식 합격 미확인:** 다른 사람이 화면을 직접 시연한 기록, 7일차 공식 접수/통과, 운영 인증 또는 v1.0 출시 근거가 아직 없다.

## 5. 동일 커밋을 다시 확인하는 방법 (Windows PowerShell)

기존 변경이 있는 폴더를 초기화하거나 덮어쓰지 않는다. 먼저 **GitHub 최신 내용을 받은 별도 깨끗한 폴더**의 Git 최상위에서 아래 명령을 한 줄씩 실행한다.

```powershell
git status --short
git rev-parse HEAD
cd on-client
node --version
npm run check
node tests/pc-status.test.mjs
node tests/windows-observation.test.mjs
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

브라우저에서 `http://127.0.0.1:5189/`을 열어 **2절 순서대로 실제로** 확인한 뒤, PowerShell 실행 창에서 `Ctrl+C`로 종료한다. 다시 실행한 결과도 별도 기록한다. **포장 명령은 실행하지 않는다.**

| 시연자가 직접 채울 기록 | 작성란 |
|---|---|
| 실측한 PC/OS와 Node 버전 | **미확인** |
| 시작·종료·재실행 확인 시각(KST) | **미확인** |
| E01/E02/E03 실제 화면 관찰 결과 | **미확인** |
| 확인 불가 항목과 오류 원문/다음 행동 | **미확인** |
| 제출용 40자리 SHA (`git rev-parse HEAD`) | **7일차 최종 커밋 후 확인** |

**학생의 시연 기록은 학생 진술이며, GitHub 원문 확인·모의 검사·실제 Windows 실행 검증·공식 AI 판정은 각각 다른 증거다.** 같은 최종 커밋의 확인 결과만 해당 버전의 결과로 묶는다.
